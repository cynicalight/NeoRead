# 文档用量统计

PDF 卡片的统计按钮位于编辑信息按钮左侧，右键菜单提供同名“用量统计”入口。处理中刷新累计结果，完成或失败后仍可查看；PDF 和 EPUB 均提供入口。窗口展示正文翻译、聊天两行；图片沉淀已移除，仅在文档有历史沉淀用量时额外显示“沉淀／图片解析”一行；阅读界面的 AI 助读页签右侧也提供聊天统计按钮。

## 统计口径

统计 PDF 本地解析、正文翻译（含公式转换），以及 PDF／EPUB 的聊天；旧版本的图片沉淀用量继续保留。学习当前是本地处理，不消耗 AI token；聊天按独立阶段汇总，能力检测和自动分类不计入总量。

每次连接尝试以独立 ID 持久保存，按文档、阶段、实际返回模型汇总。主连接失败后备用连接单独记账。失败、超时、取消和重试已返回的用量都计入；缺失用量为 null，不能用字符数估算或当作零。失败请求返回的快照可能不完整，会提示实际消耗可能更高。

输入含缓存读取和写入；输出含推理，细分项不再添加到总量。未返回细分项为 null。Codex 每次使用全新的 ephemeral thread，读取 thread/tokenUsage/updated 的线程累计 total，覆盖先前快照，避免漏掉同一线程内部重试；只接受当前 thread 的事件。实际模型来自 thread/start。Claude 使用 result.modelUsage，输入归一化为 inputTokens + cacheReadInputTokens + cacheCreationInputTokens，可记录一个请求涉及的多个模型。Chat Completions 请求 include_usage，接受成功终态之后、[DONE] 之前的 usage-only 帧。Kimi 保存会话返回的模型；当前 ACP 适配器没有已验证的生成用量字段，显示用量未知。

总经过时间从首次开始到完成，包括中间排队或暂停；失败／等待时停止增长。各阶段耗时为实际执行区间之和；并发翻译只计算阶段经过时间，不叠加各批次耗时。中断调用的准确结束时间无法恢复，明细标记结束时间未记录；崩溃时未完成的阶段区间不计入阶段耗时，避免计入停机时间。因此中断任务的阶段耗时可能不完整。

历史任务默认不具有完整统计覆盖。重试后的调用可以记录，但旧结果无法补回历史用量。重启保留调用记录，打开书库时将遗留 running 调用标记 interrupted。删除文档通过外键同时删除统计。统计表只保存计数、模型与任务标识，不保存文档正文、图片、提示、凭据或完整协议帧。

统计写入失败会停止当前生成／处理，不自动切换备用连接造成额外调用。用量元数据不会进入聊天文本或翻译 JSONL 解码器，原有流式输出与成功终态检查保持不变。

协议依据：本机 Codex App Server 的 thread/start 与 thread/tokenUsage/updated，以及 [Claude Agent SDK 用量文档](https://platform.claude.com/docs/en/agent-sdk/cost-tracking)。

## 聊天用量

文字聊天、图片聊天、选区翻译／解释和章节总结通过同一聊天生成入口记录。每次提问生成独立请求标识；各次主连接、失败和备用连接尝试归到该标识，按文档持久保存。UI 汇总提问次数、调用次数、实际返回模型、输入／输出／总 token、缓存、推理与调用结果。图片输入包含于服务返回的输入用量，当前不能与文字拆分。

聊天累计耗时是各连接尝试耗时之和，不包括两次提问之间的等待；并发调用也会各自累加。处理与聊天的 token 分阶段展示，顶部总量合并二者；累计执行耗时合并本地处理、正文翻译阶段执行区间与聊天调用耗时，不含闲置／排队时间。升级时已有聊天的文档标记历史覆盖不完整；不能补算旧聊天。清空对话保留已经发生的消耗，删除文档才级联删除统计。统计窗口打开时定时刷新，关闭后停止。

## 手动验证

1. 导入一份 PDF，卡片铅笔左侧出现统计图标；点它打开窗口，不进入阅读界面。右键“用量统计”打开相同窗口。
2. 自动翻译或点击“开始翻译”后，在翻译运行中打开窗口，检查用量和状态刷新。完成后封面进度消失，统计按钮继续保留。
3. 默认展示正文翻译、聊天两行（有历史沉淀用量时另有“沉淀／图片解析”）；点击阶段行左侧箭头展开模型详情，核对 Provider、模型、调用结果、关联调用累计耗时，以及输入、输出、缓存、推理 token。逐次调用记录保留在后台，不在窗口逐条展示。
4. 重试失败任务后确认旧调用保留，总量累加，已保存图片和翻译不会因跳过而再次计数。
5. 重启后查看统计；旧文档应提示历史用量未记录，未返回 token 的连接应显示未知。
6. 在网格／列表、浅色／深色下检查按钮位置、表格横向滚动和长模型名。EPUB 提供聊天统计，PDF 同时提供文档处理与聊天。
7. 对同一文章进行文字／图片提问；核对聊天累加而处理阶段用量不变。切换文章、刷新或重启后统计仍按文章隔离。阅读界面点击 AI 助读页签旁统计按钮，应打开同一个用量统计窗口。

自动验证覆盖累计快照去重、真实模型字段、外线程事件隔离、usage-only 帧、缓存归一化、并发写入、失败及备用调用、存储错误、重启恢复、删除级联，以及窗口入口和未知用量展示。测试不依赖真实账户调用。按照仓库要求，视觉验收由用户手动进行。

## 模型独立价格与历史估算

API 提供者管理地址、Key、协议和模型列表。获取候选列表或手填 ID 后，打开该模型一行的“模型设置”，编辑它自己的价格以及检测／生成时限。价格仅属于这个提供者下的这个模型；同提供者的其他模型、其他提供者的同名模型都不会共享单价。刷新列表、切换提供者和保存时限不会清除已保存价格，也不会自动发起检测。

价格单位为每 100 万 token，每模型显式选择 CNY 或 USD。留空或清空表示未知，显式 0 表示免费；价格必须为非负有限数值。切换币种清空当前模型表单金额。不设提供者默认价，不补入其他模型价格，不自动获取报价或换汇。

每次 API generation 解析提供者与请求模型时复制该模型价格；普通文本／图片请求和翻译在首个上游生成请求前保存，文档工具每轮与压缩调用从同一 generation 快照复制。快照包含请求模型与字段来源，不包含凭据。上游返回的模型别名使用该请求快照，不按别名重新查询价格。保存后的费用与价格不随设置变更重算，旧记录没有价格时显示未知。历史快照中的旧 provider 来源保留，新的快照来源为 model。

估算为 `(普通输入 × 输入价 + 输出 × 输出价 + 缓存读取 × 读取价 + 缓存写入 × 写入价) / 1,000,000`。普通输入从总输入扣除已知缓存读取和写入；输出已经包含推理，不另收费。例如输入 1000、读取 200、写入 100、输出 100，四项价格依次 2、8、0.5、3，费用为 0.0026。若缓存拆分未返回且对应价格不等于输入价，不能完整估算输入部分；只计可确定的部分，不将未知视为 0。缓存子集超出总输入时不产生负费用。

`ModelTokens.cost` 保存金额与 `complete`、`partial` 或 `unknown` 状态；`UsageCall.price` 保存不可变价格快照。失败或未完成调用已返回的用量可计费，但标记部分估算。统计顶部和提供者／模型明细按币种分别累计，保留未知和部分估算调用数，处理与聊天报告合并时同样按币种相加。CLI Agent 与未配置价格的备用连接显示费用未知。估算金额仅按用户填写的单价计算，不是提供者账单。

兼容先前实验配置：读取到旧 provider.pricing 时，只把已记录在手填列表、启用列表、逐模型设置和已选任务中的模型当时有效值固化为独立价格，并清除内存配置中的旧提供者字段；下一次保存配置持久化这一转换。动态目录返回的其他模型不会获配旧价格，清空独立单价后保存不会再补回。已有逐模型显式值（包括 0）、币种隔离、时限与所有历史调用记录保留。正常运行的价格解析只读取逐模型记录。

手动检查：给同一提供者的 A/B 设不同价格，再给另一提供者的 A 设第三个价格；刷新列表、切换提供者和保存模型时限后，各值保持独立。清空 A 单价后刷新仍应为未知，0 保持免费。使用临时书库完成调用后修改该模型价格，历史金额应不变。检查 CNY／USD 分列、失败和未知费用提示，以及浅色／深色与 reduced motion。
