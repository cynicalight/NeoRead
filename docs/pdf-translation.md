# PDF 翻译与对照阅读

## 导出

- 笔记栏的「导出」与论文右键菜单的「导出…」复用同一个导出弹窗。「批注 / 原文 / 译文」并排多选，Markdown / PDF 同样可多选，选中显示绿色及勾选图标。底部只有一个主题色胶囊形「导出」按钮，依次生成选中的内容与格式；取消会停止后续导出。
- 选择「批注」后显示批注、划线、高亮、问题四个独立多选项。批注文件只包含选中的批注及问题关联的回答，不包含论文信息、论文笔记、书签和独立 AI 对话。批注 PDF 按 Markdown 内容重新分页，不向原 PDF 写入标记。右键入口按当前论文读取批注与问答，读取失败可重试。
- 原文 PDF 直接下载原文件，不附加书签或批注；原文 Markdown 使用已解析的正文，按文档顺序输出。EPUB 原文 PDF 从已解析正文生成。
- 译文 Markdown 和 PDF 共用当前已保存的译文。正文默认 16px（12pt），A4 页面重新分页，不继承原 PDF 的坐标、分栏或字号。保留 Markdown 的标题、列表、表格和公式；本地图片以内嵌数据保留在 Markdown 中，并直接渲染到 PDF；图片缺失时明确报错，不再导出占位文字。未完成或未解析部分沿用译文导出的状态说明，不触发新翻译。
- 文件名统一为「论文名-批注/原文/译文.md 或 .pdf」，网页打印标题同步设置为对应文件名。桌面端直接生成 PDF；网页端打开浏览器打印窗口，可选择另存为 PDF。关闭弹窗会取消当前导出，取消后不下载迟到的结果。失败保留导出弹窗并显示错误，可重试。
- 论文右键菜单仅保留一个「导出…」入口。更多操作菜单及书库批量工具栏原有的「导出带批注的 PDF」仍将批注写入原 PDF 副本。

## 已确认的交互

- PDF 图片提问自动附带阅读顺序中图片前后最近的各一段文字，跳过图片、独立公式和页眉页脚，不判断哪一段是图注。相邻文字随问题保存供后续追问使用；文档边界缺少一侧段落时只附带已有内容。原有图片内文字和旧版图注仍保留。
- 设置 → Agent 中可保存或恢复默认翻译提示词，补充风格与术语要求。偏好应用于全文／章节和划词翻译，不改变问答、公式转换、输出格式或原文对齐规则；不会自动覆盖已有译文。
- 普通翻译尚未完成的部分在后续调用／恢复时沿用当前设置；显式重译使用确认时保存的任务选项，暂停或重启后继续使用同一组选项。
- 论文全文翻译完成后保留“✓ 翻译完成”，旁边的“重新翻译”图标打开确认框。确认后固定本次所选 Agent、翻译模型、思考档位和提示词，先重新解析整份 PDF 的版面并生成图片附件，再按新段落重新翻译、转换公式。解析成功前保留原解析结果，失败或取消不会覆盖它；本轮解析完成后暂停、继续或重启不重复解析。图书仍按章节翻译，不新增全文重译入口。
- 重译开始时以事务保留上一版成功译文。新结果通过原文对齐校验且提供方成功结束后，逐段替换；版面重解析改变段落 ID 或原文时，不强行套用旧译文；失败、暂停或重启时仍可阅读尚未替换的旧译文，继续操作只处理未完成部分。已有笔记保留，位置和摘录不再匹配的译文标注不会附着到新文字。

- 仅改变中间阅读区域，提供仅原文、原文译文、仅译文。双栏支持交换两侧，并可在左右排列和上下排列之间切换：分割线顶端（上下排列时为左端）依次是“交换原文和译文”和排列切换按钮。上下排列时分割线为横线，拖动调整高度。排列方式与交换、分栏比例一起保存，PDF 与 EPUB 共用。
- 原文保留 PDF.js 渲染、划词、笔记及高亮。文字 block hover：右上角询问 AI，右下角整段翻译。
- 译文按连续单栏排版，保留标题、段落、图表、公式和阅读顺序。双栏和仅译文共用译文。
- 新论文先本地解析，默认不超过 50 页时自动翻译；超过阈值则在解析完成后等待“翻译”。设置 → 论文库的滑块提供 0–150 页、步长 10，0 为全部手动。保留暂停与继续。详见 [翻译触发与暂停](pdf-on-demand.md)。
- 学习阶段提取正文与版面，随后进入翻译阶段。图表附件不再生成解析稿；已完成译文继续复用。
- 封面依次显示学习中、翻译中，每次只显示当前阶段。进度分别按页数、已完成翻译段落数计算；阶段完成后向上淡出，继续显示下一阶段。重启后从已保存的有效译文恢复翻译进度。
- 全文翻译逐段开放并本地保存；未完成段落显示状态，失败部分独立重试。
- 公式转换单次限时三分钟，仅超时会在一秒后自动重试一次；两次均超时保留明确的超时原因，可手动重试。暂停、取消及外层截止时间立即停止调用与重试，未完成结果不会保存。普通调用失败不改写已通过的 Agent 能力检测；能力结果只随重新检测或连接／模型配置变更更新。
- 仅原文点击段落翻译打开附近浮层，提供进入双栏入口。任务未开启或已暂停时，需要先点击主按钮开始或继续。
- 翻译摘要、标题、正文、图注、表注与脚注；图片附件仅翻译图题，公式独立转换，算法块与图表一样裁剪为原图展示，提取文字保留供检索；不再将算法排成 Markdown 代码块。算法正文不翻译，单独提取的 caption 沿用图片图题翻译规则。没有可提取文字的页面保留原页和已有图片，不标记解析错误或译文不完整；不执行 OCR。
- 双向 hover 按 blockId 对应：鼠标停在任一侧段落时，两侧显示同一段落的背景标记；离开、滚动或切换模式清除临时标记。hover 不主动滚动、不改变划词选区或持久标注。
- 双向划词采用句子级对应；跨句对应多个句子。译文划词保留实际选区，原文通过 PDF.js 文字层的完整句子 Range 与 CSS Custom Highlight API 显示浅灰色关联高亮。匹配失败的句子不画近似文本框或整段色块；文字层尚未就绪时等待渲染后重建。仅接触相邻句子边界不算选中该句。原文反向匹配缺少可靠映射时仍退回译文段落。关联高亮临时显示，与持久笔记区分。
- 原文匹配先使用精确文本；数学字母或下标被解析器移到行尾时，允许按完整正文匹配，再保留 PDF 中的实际字符范围。整段正文和数学字母集合一致时，用段落内顺序确定句子；缺少整段对应时，仅接受足够长、唯一且数学字母集合一致的完整句子。段落上下各保留一行查找余量，避免解析边框裁掉末行；该余量不直接参与绘制。
- 译文蓝色选区保留浏览器原生 Range、拖选、键盘扩选和复制行为，通过 Custom Highlight 显示贴合文字的背景，不改变阅读行距。只在自定义背景已生效时隐藏原生整行选区背景；清空选区、离开译文或关闭面板时恢复。不支持该 API 的浏览器保留原生选区。
- 原文译文始终双向同步滚动，不提供关闭开关；滚动按段落和阅读顺序定位，不按全文滚动百分比映射。程序滚动不能触发反向同步。
- 点击原文或译文的文字、图片 block，在定位期间显示灰色背景和边框，完成后淡出；询问 AI 和整段翻译按钮仍只在 hover 时出现。不提供单栏模式开关。
- 点击任一侧 block 时，两侧按各自内容尺寸平滑垂直、水平居中；高于对应视口的 block 顶部对齐。再次点击当前 block 也重新读取两个面板的尺寸，适应拖动分栏和左右交换。
- 仅原文点击聚焦使用 150%；原文译文按 block 宽度适配当前原文面板，左右预留 16px，自动缩放最高 200%。缩放和定位共用动画，手动缩放仍可自由调整。
- 页眉、页脚、页码在 PDF 中保留，但不参与 block 点击定位、hover 和翻译。沿用已有分类与坐标过滤页面装饰，保留脚注和图注。
- 聚焦是一次点击操作。完成后保留布局、缩放和滚动位置；滚动不设置焦点、不自动切段或居中，不提供上一段／下一段按钮。保留普通双向滚动同步，只按对应位置跟随，不触发点击聚焦。
- 滚轮、触控板和新的点击可中断定位动画；连续点击以最后一次为准。系统减少动态效果时直接定位并移除临时高亮。原文滚动条隐藏，保留滚轮与触控板滚动；程序滚动不触发反向同步。

## 批量流式翻译

- 按阅读顺序累计 10,000 个原文 Unicode 字符，达到目标后保留整个当前段落，在段尾切分。阈值允许超出，绝不截断段落。
- 每个正文翻译 worker 在一次运行中独立复用 Codex App Server 进程和临时 thread，后续 batch 作为新 turn。沿用主分支的翻译模型自动选择、显式模型、Effort 映射与自动模型失败回退逻辑；完成、取消或失败时清理会话，重启和重试创建新会话，已保存的译文继续复用。
- 默认并发三个 batch；空位释放后继续领取下一批。重试沿用原始批次边界，仅发送尚未完成的段落。
- 每次附带文档标题、作者、首页题名作者区域的原文资料，以及批次前后各两段原文。上下文不计入待译字符数，不额外输出译文。
- Prompt 为每段提供稳定的 blockId、sourceHash 和 source。每行 JSONL 必须原样返回对应 ID 与 hash，并输出按序覆盖原文的 sentences；禁止合并或拆分段落，禁止输出上下文段落。
- PDF 提取文字可能有单词内多余空格、断行连字符和错位的数学斜体字母。Prompt 允许模型在确定时做最小修正，不确定时保持原样。服务器先比较去空白后的原文；不一致时只比较字母（去掉数学斜体、数字、空格和标点），共同字母须超过较长一方的 50% 才接受。接受后保存模型的句子作为 `source`，并用最长公共子序列把每句对齐到提取原文，存为 `anchor`，阅读器用它在 PDF 文字层中定位句子。
- 文字重排的原文：完整翻译的段落按句显示模型修正后的 `source`。补回行内公式的句子总是显示；其他修正需与提取原文的共同字符达到较长一方的 90%（忽略空白与软连字符，数学斜体等兼容字符按 NFKC 归一）才显示，否则显示提取原文。未翻译或未完成的段落显示提取原文。选区、引用、笔记高亮和关联高亮通过 `anchor` 映射回提取原文，复制段落也复制修正后的原文。
- 译文中的行内数学一律写成 KaTeX 可解析的 LaTeX（如 `$T_i$`、`$MVSG(s, \ll)$`），由译文 Markdown 渲染；能确定时还原被提取打散的下标，不确定时照抄原文符号。普通美元符号写成 `\$`，不输出 `$$` 独立公式（独立公式块仍由公式图片转换），JSON 中反斜杠须转义。`sentences.source` 仍按原文复制。修改规则不会触发已保存译文的重译。
- 增量片段只缓存尚未收齐的一行。完整行立即解析、校验、落库并发布 SSE 事件，不等 batch 完成。无换行尾行只有在 provider 成功结束且 JSON 完整时接受。
- 未知 ID、错版本、缺句、重复行不能覆盖已完成段落。中断保留已保存结果，重试只补失败或缺失部分。
- GET `/api/documents/{id}/translations/stream` 使用现有会话认证。连接建立时先发 `snapshot`（段落数组），随后每次保存发 `translation`（单段）；每个事件立即 flush。断线重连重新获取快照，不使用定时 GET 轮询。
- 前端按 blockId 更新对应位置，各 batch 的返回顺序不会改变文档顺序。关闭阅读界面只关闭订阅；已授权的当前范围任务继续，随阅读模式不自动扩大范围。
- 翻译请求上限为每批 20 分钟，其他生成请求仍为原有三分钟；沿用生成器的输出大小限制。超出限制的长段落完整保留为失败待重试，不硬切原文。

## 实现边界

- 原始 PDF、既有笔记及图表解析稿不覆盖。翻译采用按段提交：完整 JSONL 行通过段落 ID、原文版本与句子覆盖校验后立即保存并显示。已保存的段落不依赖整个 provider 请求最终成功；聊天仍保留原有完成后保存规则。
- 翻译内容作为不可信资料，只用于生成内容，不授予执行工具的权限。
- 翻译缓存与原文版本绑定，句子覆盖必须完整且保持顺序；不可靠映射不得伪装为精确对应。
- PDF.js 保留原文的多栏、标题和图表布局，是原文渲染与文字选择的唯一引擎。点击定位使用已有 block 坐标，不再推断正文栏或自动导航。
- 译文侧标注保留其语言和文字范围，同时关联到原文位置，不能把译文引用误当作原文搜索词。
- 自动跟随尊重手动缩放；主动侧控制同步，模式切换和 resize 尽量保持阅读位置。

## 验证

重点覆盖翻译中断恢复、失败重试、来源变更、句子范围、同步回环、点击定位、尺寸变化及动画中断。
完成 `pnpm typecheck`、`pnpm test`、`pnpm build`。不使用浏览器自动化进行视觉验收；用真实双栏和混排论文手动检查。

`apps/web/src/readers/fixtures/oze-sentence-alignment.json` 保留 Oze 第 6 页 `p6-b4` 的实际解析文本、缓存句子及 PDF.js 文字片段与坐标，用于复现下标错位和末行裁切。回归测试检查实际 PDF 字符范围，不能仅以规则排版的手写句子代替真实论文数据。

## 原文块修复

- 文字坐标统一使用有效的字体 ascent；为零或无效时依次使用有效 descent 和 0.8 的回退值。正文提取和前端句子定位共用这条规则。
- 同一栏中互不重叠的块按上下位置约束排序；跨栏部分保留模型顺序，全宽区域约束两侧。排序不改变现有缓存的 block ID、矩形和图片引用。
- `node apps/processor/dist/repair-text.mjs --input PDF --manifest 原缓存/manifest.json --output 空目录` 可生成修复候选，不重新调用 Paddle，也不覆盖原缓存。输入 PDF 必须匹配原 manifest 的 SHA256。
- 发布候选前停止对应 NeoRead 实例，备份原 `manifest.json` 和 `paper.md`，核对 ID、矩形和资源引用不变，再替换这两个文件。原笔记、图表解释和历史译文保留。重启后按原文 hash 复用未变化的译文，变化的段落在用户开启辅助阅读且进入处理范围后才重新翻译；旧译文上的标注不会错误贴到新版本文字。
