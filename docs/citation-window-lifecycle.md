# 引注窗口与应用生命周期

## 设计依据

Word/WPS 插件通过本机 HTTP 向 Go 服务发送请求。Electron 主进程持续订阅经过认证的 `/api/cite/events`，收到请求后才创建该请求的渲染窗口。应用启动时不创建引注窗口，主书库窗口也不负责订阅引注事件。

Zotero 的集成实现也将命令接收与对话框分开：`initPipe` 把命令交给 `execCommand`；需要交互时，`displayDialog` 创建窗口，并在窗口卸载时清除引用；`execCommand` 的 `finally` 关闭剩余对话框、清理文档会话并恢复文档焦点。这里只参考生命周期设计，没有复制 Zotero 实现或改变 NeoRead 的 Word 协议。

核对源码：[Zotero integration.js，提交 212a7d6](https://github.com/zotero/zotero/blob/212a7d6a585d1209bc4e698a904490205f139500/chrome/content/zotero/xpcom/integration.js)。不同平台的插件传输并不相同，不能把 Zotero 的全部 Word 集成都称为 HTTP；NeoRead 自身继续使用现有 HTTP 接口。

## 一次引注请求

1. Go 验证请求并创建事务，沿用已有单事务限制。再次点击时返回忙碌，并请求聚焦当前对话框。
2. Electron 主进程保存命令并创建临时窗口。渲染进程订阅 IPC 后报告准备完成，主进程才交付命令，避免首次请求在加载期间丢失。
3. 渲染进程运行既有引注会话，通过 Go 与 Word/WPS 交换文档操作。需要用户选择时显示窗口；刷新等无交互操作不显示窗口，但在本次请求期间使用临时渲染进程运行现有排版逻辑。
4. 操作完成或用户取消后，主进程销毁窗口并向 Go 完成事务；Word/WPS 收到原有 `Document.complete`。下次请求创建新的窗口，不保留空闲引注渲染进程。
5. 加载失败、15 秒内未准备好、原生窗口关闭或渲染进程崩溃时，主进程终止事务。事件连接断开时销毁该次窗口；Go 既有断连处理取消失去订阅者的事务。连接恢复后不重放旧的文档修改。

准备完成和完成事务的 IPC 校验当前引注窗口及其主 frame，完成请求还需匹配当前事务。窗口关闭后移除其 IPC 处理器，主进程停止后移除服务监听。

## 系统退出习惯

| 操作                   | Windows / Linux                              | macOS                                                      |
| ---------------------- | -------------------------------------------- | ---------------------------------------------------------- |
| 关闭主窗口             | 等待保存后退出应用，包括引注服务和 Go 子进程 | 等待保存后销毁主窗口，保留 Go 与主进程引注服务             |
| 再次打开应用           | 启动应用；已有主窗口时恢复并聚焦             | Dock 激活、再次启动、打开文档或 NeoRead 链接均可重建主窗口 |
| 明确退出 / `⌘Q`        | 等待保存后停止服务并退出                     | 同左；即使主窗口已关闭也停止服务                           |
| 保存失败，选择返回阅读 | 保留窗口和服务，撤销此次退出                 | 同左                                                       |

重建主窗口只重新创建窗口及其更新检查服务，应用级 IPC 和 Go 服务只初始化一次。每次关闭都重新等待阅读数据保存。书库迁移和重启仍走明确退出路径。

Go 服务启动成功后意外退出时，无论主窗口是否存在，都停止引注订阅、阻止重新打开窗口，并显示原生故障提示。用户关闭提示后退出整个应用，下次启动重新创建服务；不在当前进程中自动重启服务。启动阶段失败沿用启动故障提示，正常退出不重复报错。

## 诊断与验收

主进程记录 `citation.window_created`、`citation.completed`、窗口加载失败/超时/关闭、渲染进程退出及事件连接断开/恢复。日志仅记录固定事件名，不记录文档内容、请求正文、插件凭据或 token。连续连接失败只在首次记录断开，成功连接后恢复记录。

自动回归覆盖首次请求交付、重复准备消息、连续请求、完成销毁、加载失败、原生关闭、崩溃、连接中断、准备超时及 IPC 来源验证；应用生命周期测试覆盖 Windows 带辅助窗口退出、macOS 主窗口重建、无主窗口退出和保存失败取消退出。OS 边界使用 mock，这些测试不能替代真实 Word、Windows 和 macOS 的手动验收。

手动验收：

- 启动 NeoRead 后，不操作 Word，不应存在引注窗口。
- 在 Word 连续执行两次插入引注，每次均能打开、完成或取消，完成后不留空闲引注窗口。
- Windows 关闭主窗口后进程退出，再次双击正常打开；关闭时有引注窗口也应退出。
- macOS 关闭主窗口后仍可从 Word 发起引注，点击 Dock 能重新打开书库，连续关闭和打开不会重复处理请求。
- macOS 在主窗口已关闭和仍打开两种状态下使用 `⌘Q`，都应退出；保存失败选择返回阅读时不退出。
- 引注期间关闭 Word、终止引注渲染进程或制造页面加载失败，事务应结束，重新发起请求可用。

本次不修改 Word VBA、Ribbon 或插件模板文件，无需因协议变化重新安装插件。
