# Side chat 多会话

打开任一 PDF/EPUB，在右侧 Agent 面板顶部选择会话，点击加号新建，铅笔按钮重命名。在设置中选择模型连接。所有侧栏会话均由内置 Pi 执行，旧记录自动归入默认会话。

会话之间的问题、上下文、引用和输出独立。可以在会话 A 等待回答时切换到 B 提问，再切回 A 查看进展。关闭侧栏或切换文档不会停止生成；只有点击停止、删除文档或退出 NeoRead 才会中断相应运行。最多四个会话同时运行，同一会话一次只处理一个问题。退出应用后的在途请求不会在下次启动时自动重发。

各会话的新消息和重新生成使用设置中当前选定的后端；模型与 Effort 复用对应后端的偏好。已开始的运行保留开始时的配置，切换设置不改变在途请求。账号授权和 API Key 在 Agent 设置中配置。论文仍是阅读单元，普通问答不提供项目目录、终端或自动写文件。

## 输入框命令

在 Agent 输入框开头输入 `/` 打开命令列表。继续输入可筛选，按 ↑ / ↓ 移动，按 Enter 或 Tab 选择，按 Esc 关闭。没有匹配项或已关闭列表时，以 `/` 开头的内容仍可作为普通文字发送。

- `/new`：在当前文档新建会话；如果当前已是没有消息的「新会话」，就留在该会话。
- `/exit`：收起 Agent 面板，不删除会话，也不停止正在生成的回答。
- `/prompt`：从已保存的常用 Prompt 中选择一条，填入输入框。可以继续编辑，确认后再发送。
- `/create-skill [需求]`：打开技能编辑表单。需求可省略；不输入需求时可手动填写技能。
- `/<技能名>`：为下一条问题添加可移除的技能标签。选好后再输入问题并发送；发送后不会自动将技能附到下一条问题。会话记录在这条问题旁显示技能名。

NeoRead 从 `~/.agents/skills`、`~/.claude/skills`、`~/.codex/skills` 的直接子目录发现 `SKILL.md`，读取文件开头 YAML 中的 `name` 和 `description`。技能目录或 `SKILL.md` 可以是指向其他位置的符号链接；最终只读取不超过 64 KiB 的普通 `SKILL.md` 文件。同名技能按上述顺序选用第一项。

发送时，所选技能的正文会作为本条问题的指令交给当前模型。技能不会扩大 Agent 的权限：模型仍在当前文档的问答环境中工作，不会因此获得文件或终端工具，不能读取技能目录中的其他文件或运行脚本。技能正文仍可能保留在该会话的模型历史里，影响后续回答；如需不带这段历史提问，请新建会话。

### 创建技能

在输入框键入 `/create-skill` 后按 Enter，可直接填写技能名称、描述和 Markdown 正文。键入 `/create-skill 需求` 后按 Enter，则会用当前配置的模型生成可编辑的草稿。预览并确认内容后才会保存；取消不会写文件。创建命令和草稿不会作为消息写入会话，也不会自动把新技能附到下一条问题。

生成草稿时，NeoRead 使用 Agent 设置中当前选定的主模型连接，发送需求和当前文档所选会话中最近最多 12 条用户与助手消息的文本（每条最多 1024 个 Unicode 字符）。会话只决定使用哪些消息，不决定模型连接。未指定会话时使用默认会话；没有默认会话时只使用当前文档中未归入会话的旧消息。不会额外读取或发送文档原文、元数据、引用、附件或模型思考内容。手动编辑和保存无需调用模型。

确认后，NeoRead 将名称和描述写入 YAML 文件头，将正文写入 `~/.agents/skills/<技能名>/SKILL.md`，然后即可从命令列表选择该技能。如果这个目标文件已经存在，必须另行确认覆盖；不确认就不会改动原文件。符号链接目录只可读取，不能从这里保存或覆盖；请改用其他名称或在原位置编辑。其他目录中的同名技能不会被改动，但保存到 `~/.agents/skills` 的版本会优先使用。

接口分为两步：`POST /api/skills/draft` 接收 `documentId`、可选的 `sessionId` 和 `request`，返回 `name`、`description`、`body`；手动创建跳过这一步。确认保存时才将编辑后的这三个字段与 `overwrite: false` 提交给 `POST /api/skills`。仅在收到 `409` 且用户确认覆盖后，才以 `overwrite: true` 重试。

## 开发验证

在任务 worktree 执行 `pnpm install --frozen-lockfile`、`pnpm typecheck`、`pnpm test`、`pnpm build`。`pnpm dev` 会同时构建并启用 pi worker；直接启动 Go 时需设置 `NEOREAD_NODE` 与 `NEOREAD_AGENT`，后者指向 `apps/agent/dist/main.mjs` 的绝对路径。

1. 导入 PDF 或 EPUB，确认默认会话里的旧消息、来源跳转、批注关联保持可用。
2. 新建两个会话，分别问两个不同问题。在 A 出流时切到 B 发送，确认两者都继续运行。
3. A 运行时切换论文或关闭侧栏，再回到 A，确认可以继续查看输出与最终保存结果。
4. 同时运行 A/B，停止 A，确认 B 正常完成；重命名和切换不会改变各自的上下文。
5. 刷新页面时保留正在运行的会话，确认接回同一 run；退出 NeoRead 再打开，确认未完成问题显示可重试，没有自动重复发送。
6. 在设置中分别切换 ChatGPT、Claude、Kimi Code 或 API Key 连接，确认已有会话和新会话的下一次发送都使用当前设置；使用选文、PDF 图表附件与 EPUB 阅读位置继续提问，核对增量输出、来源与定位。真实连接需要有效的账号或 API Key。
7. 分别从空需求手动创建和从需求生成草稿，确认预览可编辑、取消不保存、确认后可从命令列表选择；再次保存同名技能，确认拒绝覆盖时原内容不变，确认覆盖后使用新内容。

自动化测试使用本地模拟模型服务和 Pi worker，不调用付费模型或读取真实 CLI 凭据。视觉和真实账号验收需按上述步骤手动完成。
