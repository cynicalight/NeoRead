# Reader 多提供商、模型与成本配置方案草案

状态：分支实现中的方案，已按 2026-10-15 用户更正更新价格语义；与更新限流 PR 分开。

用户更正：API 提供者管理连接和模型列表，价格属于提供者下的每一个模型。此前“提供商默认价 + 模型覆盖”的建议不符合需求，已取消；每模型独立设置价格和时限。
基于 upstream/main c7ddc91，2026-10-15。

## 目标

用户能保存多个第三方 API 提供商，仅启用自己选择的模型；针对慢接口分别配置检测和实际使用的等待时间；为各提供者下的模型分别设定独立价格，在现有用量界面看到估算费用。

用户已确认参考项目为 Pi Agent 和 DeepSeek Harness。以下参考来自它们的官方仓库；Reader 的超时策略、逐模型价格编辑和币种方案是本项目实现。

## 已核对的开源参考

- [Pi 模型配置](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/models.md)：按提供商组织端点和模型，允许自定义模型及覆盖已有模型元数据。`/scoped-models` 是快速切换的范围，不等同于检测通过的模型名单。
- [Pi 配置 schema](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/schemas/models.schema.json)：模型价格包含输入、输出、缓存读取、缓存写入，单位为美元 / 百万 token。价格位于提供者下的模型记录（models[].cost / modelOverrides.<id>.cost）。Reader 参考这些价格字段，按模型独立保存并区分币种。
- [DeepSeek Harness 提供商设置](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/providers.zh.md)：自定义提供商填写端点、协议和凭据，获取候选模型后勾选添加，也支持直接输入模型 ID；模型发现失败不妨碍手工配置。已核对 DSH 的 ModelListEditor/ProviderEditor：它提供“提供者连接 + 独立模型行”的组织方式，当前模型编辑 UI 没有价格字段；Reader 的价格表单并非照搬 DSH。
- [DSH 的 Pi 适配层](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/llm/llm-pi-ai/README.zh.md)：DSH 使用 Pi 支持多个提供商。Reader 已有 Go 调用层，建议借鉴配置与交互，保留现有协议实现；引入整套 Node Agent 运行时会扩大此次改动范围。

两项目采用 MIT 许可证；当前仅参考设计，未复制源代码。若后续复用代码，应保留相应许可与署名。

## 在 Reader 中的操作流程

1. 添加提供商，填写名称、API 地址、协议和 Key。
2. 获取候选模型并勾选，或手动输入模型 ID；只有用户启用的模型进入用途选择列表。
3. 按需要检查选中模型的文本或图片能力；显示检测阶段、耗时与错误原因。超时仅说明本次验证失败，不能直接认定模型不可用。
4. 分别为问答、翻译和图片理解选择“提供商 / 模型”，支持同一提供商多个模型和不同提供商同名模型。
5. 打开每一行的“模型设置”，分别编辑该模型自己的价格、检测和生成时限。模型价格不从其他模型或提供者继承；时限沿用现有提供者默认值和逐模型调整。

普通配置使用表单完成。获取模型列表、选择启用模型、发起能力检测是三个独立操作，重新打开设置不应自动检测全部候选模型。

## 已有能力

- 当前只有一份主要 API 连接配置，支持 OpenAI Chat Completions 和 Anthropic Messages。
- 模型列表来自 /models 加手工添加 ID，可分别选择问答、翻译、图片模型。
- 文本检测 45 秒、图片检测 90 秒；模型列表请求 20 秒。
- GenerationService 通常整体限制 3 分钟，文档 Agent 对话为 10 分钟。图片对话等调用入口也有独立限制，需统一检查父上下文，避免设置更长时间仍被外层取消。
- 已记录输入、输出、缓存读取、缓存写入、推理 token，且总输入包含缓存、总输出包含推理。不能重复计费。
- 现有统计有未知用量、部分用量和失败次数，适合在其上扩展估算费用。

## 推荐配置结构

提供商：稳定 ID、显示名称、API 地址、协议、Key、默认超时、模型列表。

模型：稳定内部 ID、API model ID、名称、是否启用、用途、能力检测状态、可选超时设置和独立价格。

同一个 API model ID 在不同提供商下是不同配置项。任务选择、检测结果、用量归属都需要包含 provider ID，不能只按模型名称区分。

启用模型列表由用户明确选择；自动拉取模型仅用于候选选择。只检测已启用模型，保持逐模型手动检测，并限制检测并发。文本通过后是否测试图片取决于所选用途，避免只用文字却强制做图片请求。

兼容旧数据：迁移现有 API 配置为一个提供商，保留现有模型选择和能力记录；不能把修改配置变成丢失 Key、历史记录或任务选项。

## 超时应分开

| 配置 | 含义 |
| --- | --- |
| 文本 / 图片能力检测超时 | 一次检测从开始到完成的总时限，用户可以调长 |
| 首个有效输出等待时间 | 正常生成在没有内容或有效进度前最多等多久 |
| 流式输出空闲超时 | 生成过程中连续多久没有有效内容或进度才取消 |
| 整次请求上限 | 防止一直运行的请求长期占用资源；应独立于空闲超时 |

“首次检测”与“首个 token”是两个概念。模型检测是验证能力的独立请求；正常聊天、翻译、图片处理是实际业务请求。

配置可先放提供商级，模型未填写时继承；任务现有更长时限需要有明确优先级。默认值和允许范围应在实施前明确，不能只增大一个内层 timeout 就宣称所有路径都支持。

网络超时或限流应显示“暂时无法验证”，同时保留上次成功时间；鉴权错误、模型不存在和确实不支持图片应明确区分。保留历史成功不等于忽略明确的权限或能力错误。

## 自定义价格与成本

- 价格只属于选定提供者下的单个模型，不设提供者默认价格，不从其他模型补值。清空单价即未知，明确填写 0 才表示免费。
- 以每百万 token 为统一单位，区分普通输入、输出、缓存读取和缓存写入。
- 每模型价格显式选择 CNY 或 USD；不同币种分别汇总，不在首版引入自动汇率。
- 根据实际返回的 usage 计算估算费用；API 未返回 usage 时保留未知状态，不能算作零费用。
- 旧实验格式的提供者默认价只在兼容转换时固化到已经配置的模型，然后清除；之后发现的模型保持未定价，清空的模型单价不得恢复。
- 价格快照随调用保存。修改价格影响新调用，历史费用保留当时价格，避免历史账单被重算。
- 缓存 token 从总输入中分离计价，推理 token 已包含在总输出中，不能重复相加。提供商未报告可分离用量时明确估算的不完整性。
- 复用现有按文档、阶段、提供商、模型的用量统计，显示费用、未知用量次数和价格来源。
- 首版用于成本可见性，不自动承诺与服务商账单完全一致；预算提醒或达到上限停止属于后续独立功能。

## 建议实施顺序

1. 检测时间配置、失败分类与仅检测选中模型，先改善当前可用性问题。
2. 多提供商配置及旧配置迁移，贯通问答 / 翻译 / 图片模型选择与用量归属。
3. 自定义价格、调用价格快照与费用展示。

每一步独立验证并形成可评审提交。对上游提交涉及配置结构的大改前，先与作者沟通范围；本次未替用户发布相关 issue 或评论。

## 必要验证

- 慢 API 在配置时限内通过；超出时限按明确阶段报错；用户取消能立即中止。
- 已持续输出不会因首输出时限被错误取消；无进度流能按空闲超时结束。
- 未选模型不发检测请求，重开设置不会扩大检测范围。
- 两个提供商存在同名模型时，Key、检测结果、用途选择和费用不串用。
- 迁移旧配置后问答、翻译、图片调用仍可用，凭据不会出现在前端响应或诊断导出。
- 零价格、缺失价格、未知 usage、缓存计价、失败但已消耗 token、历史价格和币种隔离均有回归测试。
