# Windows 安装与书库安全

App 的书库导入和迁移要求书库与应用安装目录相互独立。书库不能位于安装目录内，安装目录也不能位于书库内。可使用 `E:\Apps\NeoRead` 安装应用，在 `E:\NeoReadLibrary` 保存书库。

设置中的“迁移书库”和“导入已有书库”都会在停止本地服务、复制或保存路径之前检查重叠关系，并提示应用与数据分离的原因。检查同时覆盖路径边界、Windows 大小写和目录链接。开发模式不限制开发用书库的位置。

Windows 安装器在主安装 Section 之前检查本次选定位置、HKCU/HKLM 中的旧安装位置以及卸载命令对应的位置。仅在这些目录本身或其子目录发现 `neoread.sqlite` / `reader.sqlite` 时提示书库风险。父目录和兄弟目录中的书库不触发安装警告。检查不读取数据库或修改书库。

每次枚举前清除 NSIS 错误标志，避免上一轮扫描结束的状态导致误报。目录不存在、无法枚举或目录链接本身不作为发现书库的证据。目录链接只检查链接根部是否存在数据库，不递归遍历链接，以避免目录循环。扫描失败或跳过链接会记录 `library.install_scan_skipped`。

## 在升级时保留旧书库

旧版卸载前，安装器会显示检测到的书库路径。选择迁移，然后选择**安装目录之外的父文件夹**。例如，应用安装在 `E:\Apps\NeoRead` 时，可以选 `E:\Apps`，新书库就是与应用平行的 `E:\Apps\NeoRead Library`；不要选 `E:\Apps\NeoRead`。请先退出正在使用这个书库的 NeoRead。

新建的是**旧库的完整副本，不是空库**。安装器不会覆盖已有的同名文件夹。复制并校验成功后才保存新位置并继续升级；新版直接使用迁移后的书库，不需要手动导入。旧位置在安装目录内，随后可能被旧版卸载程序清理。

不想迁移时可以取消安装，先自行备份。明确选择跳过迁移并继续安装可能丢失数据。迁移失败、目标位置不安全或检测到多处书库时，不要用“继续安装”代替备份。

迁移失败时，安装器会根据原因提示关闭占用书库的程序、换到有足够空间的位置，或检查书库及设置目录。每次尝试独立记录 `library.install_migration.start` 和 `library.install_migration.finish`；终态包含阶段、结果、耗时和失败原因码，不记录书库路径或原始错误。可在 NeoRead 的「导出诊断包」中查看。日志目录不安全或不可写时，不向别处写日志，安装器仍会显示相应提示。

从应用内点击“下载并安装”时，即使更新器以 `/S --updated` 启动，检测到书库也要询问。单独用 `/S` 做无人值守部署不会弹出选择窗口；部署前请先在安装目录外备份数据。

## 验证

自动检查：

```sh
pnpm exec vitest run apps/desktop/main/library-path-safety.test.ts apps/desktop/main/library-location.test.ts apps/desktop/main/library-migration-lifecycle.test.ts
pnpm typecheck
# Windows 运行安装器回归时需要先构建迁移程序
pnpm build:server
node scripts/check-library-installer.mjs
```

最后一项需要 `makensis`。编译安装器和卸载器分支可以检查 hook 的顺序，但不能代替 Windows 实机升级验收。

Windows 人工验收应使用临时测试数据，覆盖：

- 安装于 `E:\Apps\NeoRead`，导入或迁移到其内部及父级书库时阻止；独立 `E:\NeoReadLibrary` 正常。
- 把有论文和笔记的测试库放在旧安装目录下，运行新版安装器，选择迁移到平行目录；升级后直接打开原论文，确认笔记、批注、附件仍可读。另用 `reader.sqlite` 旧库按相同步骤验证。
- 从旧版应用内发起更新也应能在有风险时选择迁移；无风险的常规升级不应要求选择书库。
- 改选新版安装位置时仍要检查旧安装目录。父目录或平行目录里的书库不触发安装警告。
- 选择安装目录内部、选择已有同名文件夹、保持旧库占用、取消选址，均不应因迁移而卸载旧版或覆盖数据。

本保护只包含此改动之后生成的安装包，无法改变已经分发的旧安装器。
