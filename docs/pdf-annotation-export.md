# 导出带批注的 PDF

把 NeoRead 中的 PDF 批注写进一份 PDF 副本，可在“预览”、Acrobat、Chrome、Zotero 等其他阅读器中查看。原文件不变。

## 入口

- 笔记栏 → 导出 → “导出批注与笔记”对话框底部的“导出 PDF”（仅 PDF）。
- 论文库或图书库中右键一份 PDF → “导出带批注的 PDF”。

导出期间显示进度提示，完成后显示写入的批注数；无法定位的批注单独说明数量。没有批注或全部无法定位时不保存文件。文件名为“标题-批注.pdf”，在 Electron 中弹出保存对话框。

## 写入方式

| NeoRead 批注 | PDF 中                                                   |
| ----------- | -------------------------------------------------------- |
| 高亮        | 同色高亮（半透明，正片叠底）                             |
| 下划线      | 每行底部 1.5 pt 的同色细条（与阅读器中 2 px 下划线一致） |
| 笔记        | 高亮，笔记内容写成评论                                   |
| 问题        | 高亮，评论为“问题：…”；已有 AI 回答时追加“回答：…”       |
| 书签        | 不导出（PDF 没有对应的批注类型）                         |

高亮附带的笔记同样写成评论。评论作者为“NeoRead”，时间为批注创建时间。

下划线写成高亮类型的细条而不是 Ink 线条：macOS“预览”（PDFKit）会把 Ink 批注画成白色，而高亮在 PDFKit 中按原色显示。

## 位置

- 原文上的批注保存的是相对于显示页面的矩形。导出时只合并同一行上相交或紧邻的框（`getClientRects()` 会返回重叠的重复框），双栏中同一高度的左右两栏保持分开；再用 PDF.js 视口换算回 PDF 坐标，因此带 `/Rotate` 的页面和原点不在 (0, 0) 的 MediaBox/CropBox 都落在正确位置。
- 译文上的批注不写入原文 PDF，计入提示中的“译文批注或无法定位”。它们随“译文 PDF”导出，见下节。
- 一条批注要么完整写入，要么整体跳过并计入“无法定位”，不会只写入其中一部分。

## 译文 PDF 中的批注

导出窗口选择“译文”+ PDF，或库中导出译文 PDF 时，前端以 `GET /api/documents/{id}/translations/export?format=markdown&annotations=1` 请求译文 Markdown。服务端（`translation_export_marks.go`）把译文侧批注写入该 Markdown；单独导出的译文 Markdown 和 ZIP 不带批注。

- 定位：按 `translation.ranges`（旧记录用顶层 `translation`）中的段落 ID、`sourceHash` 与句子序号匹配当前译文；源哈希不同或句子已不存在时，不挂到无关文字上，统一列入文末“未定位的译文批注”。
- 标记：在所选句子的译文 Markdown 中查找选中文字，多处出现时取最接近保存偏移的一处，可跨句。选区只允许落在普通文字中；落在公式、代码、链接、表格分隔或行首块标记中时不在正文标记，改为在批注条目中引用原文字。整句恢复的批注标记整句。
- 写法：标记写成片段链接 `[文字](#neoread-mark-0-<类型>-<颜色>)`，编号写成空链接 `[](#neoread-mark-<编号>-…)`。`markdown-pdf.tsx` 把它们渲染为同色高亮（划线为同色下划线）和上标编号。重叠的批注拆成相邻片段，每段按最后创建的批注着色。
- 内容：有笔记或问题的批注，以及无法在正文标记的批注，按出现顺序编号，以引用块写在所在段落之后；问题附 AI 回答。笔记中的粘贴图片内联为 data URI，读取不到的图片显示占位。

## 实现

`apps/web/src/readers/pdf-export.ts` 通过 PDF.js 的 `annotationStorage` 写入新批注，再用 `saveDocument()` 做增量保存：原始字节保持为文件前缀，新对象和交叉引用追加在末尾，已有的 PDF 批注和书签保留。高亮带外观流，不依赖阅读器自行生成。`apps/web/src/annotated-pdf-export.ts` 读取批注与对话（问题的回答），按需加载 PDF.js 后导出并下载。

PDF.js 新建批注的数据格式属于其内部格式（`pdfjs_internal_editor_` 前缀与编辑器序列化字段），升级 `pdfjs-dist` 时由测试兜底。

## 验证

自动测试用真实 PDF.js 导出再重新打开：高亮颜色与评论、问题与回答、下划线细条的位置与厚度、书签与越界页跳过、原始字节为前缀；旋转 90° 且 MediaBox 有偏移的页面坐标；译文批注不写入原文；导出入口的批注筛选、回答映射、文件名与提示。服务端测试覆盖译文 PDF 的跨句标记、重叠着色与编号、公式内选区回退为引用、源哈希失效进入未定位列表、普通译文 Markdown 不变；前端测试覆盖标记链接的渲染。

已用 macOS PDFKit（与“预览”相同）渲染导出的样例，确认高亮和下划线细条的位置与颜色。

手动检查：

1. 在一篇 PDF 上分别做高亮、下划线、带笔记的高亮、问题（含 AI 回答），并在译文上划一句高亮、写一条笔记。
2. 从笔记栏导出对话框和库中右键分别导出，确认提示的数量。
3. 用“预览”、Chrome、Acrobat 打开副本，检查位置、颜色和评论内容，确认原文 PDF 中没有译文批注；原文件不变。再导出译文 PDF，确认译文批注的高亮、编号和段后批注内容。
4. 对扫描版或旋转页面的 PDF 重复一次。
