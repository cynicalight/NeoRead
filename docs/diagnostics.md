# 本地日志与诊断包

Reader 持续保存本地运行日志。用户在「设置 → 诊断 → 导出全部日志」或原生「帮助 → 导出诊断包」选择保存位置，生成 ZIP 后自行发送给开发者。没有自动上传。

桌面版的代理设置和 ChatGPT 连接检测也在「设置 → 诊断」中，可先排查连接，再按需导出日志。检测固定访问 `https://chatgpt.com/robots.txt`；跟随系统模式检测当前已生效配置，切换系统代理后需重启 Reader。

## 导出范围

导出当前保留的全部 Reader 运行日志，包括正常、警告和错误事件、轮转文件以及之前的应用会话。不是仅提取错误或故障前后的时间窗口。功能上线前没有记录的历史和已经被保留策略删除的文件不能恢复。

桌面运行日志在应用 `userData/logs` 下；正式版与 `Reader Dev` 的路径分开。Go 服务通过 `--logs` 和 `--session` 使用同一目录与会话 ID，每个进程写独立文件。独立服务默认使用 `<library>/logs`。日志单文件约 5 MiB，运行日志按最后修改时间最多保留 7 天、目录总量约 100 MiB；启动和轮转时以及运行中定期清理最旧文件。

原有 `<library>/cache/<documentId>/translation-failures/*.txt` 也纳入导出。它们继续遵循原有每份文档最多 10 个文件的保留策略，不在运行日志目录的 100 MiB 限额内。导出不修改或删除这些源文件。

ZIP 包含：

- `logs/`：桌面生命周期、Go 请求及后台任务、AI 调用阶段、前端 API 和异常、服务标准错误。
- `legacy/translation-failures/`：已有翻译失败诊断，移除原始模型输出，新文件保留段落 ID、失败原因和全部尝试的解析统计。旧的交错格式在首次正文标记后全部移除，因此旧文件后续尝试的统计也会一并隐藏，避免模型伪造分隔符泄漏正文。
- `environment.json`：应用版本、构建提交、操作系统和架构、桌面运行时与时区；服务启动日志含 Go 版本。
- `settings.json`：白名单中的阅读/界面设置、主 Provider、聊天和翻译模型。桌面主进程缓存这些信息，服务退出后仍可导出。
- `manifest.json`：格式版本、导出时间、文件列表与修改时间、缺失/跳过的文件、日志写入失败次数、保留与脱敏规则。
- `README.txt`：供用户反馈时填写发生时间、操作步骤、预期和实际结果的提示。

日志按时间及 `sessionId`、`requestId`、后台 `taskId`、模型调用 `attemptId` 关联。HTTP 响应头 `X-Reader-Request-ID` 连接前后端；不改变聊天 SSE 事件和完成保存语义。日志记录阶段与结果，不记录滚动、鼠标移动或每个生成片段。

## 脱敏与边界

新日志不附带请求/响应正文、文档正文、聊天、批注、附件、剪贴板或环境变量全集。HTTP 失败只记录状态、稳定错误码和请求关联 ID，用户可见错误文案仍返回界面，但不落入日志，因为文案可能包含论文标题或裸主机名。导出同时移除旧日志中的 `userMessage` 字段；被截断的旧记录也不会保留该字段后的动态文案。前端异常记录异常类型和调用栈，丢弃可能含任意内容的异常消息首行。

采集和导出均处理结构化凭据字段、已知会话凭据、Bearer/Basic 认证、常见密钥和 JWT、URL、用户目录与 Windows 路径。URL 整体替换，避免查询参数、用户名或路径内携带凭据。旧翻译诊断的原始模型正文整体移除。原文件不变，ZIP 仅收集固定日志目录和固定翻译诊断路径，不递归打包书库、不读取 CLI 凭据文件，不包含 SQLite、PDF/EPUB、聊天或批注数据。

只接受固定字段、有限长度的渲染进程事件；IPC 校验主窗口和主 frame，浏览器模式 API 使用现有本地认证。符号链接、非普通文件和超过 32 MiB 的异常日志文件被跳过并记入清单，避免把其他文件或无界内容带入包。文件在导出时按快照长度读取，ZIP 逐文件压缩，不将所有日志同时装入内存。

脱敏针对 Reader 的日志字段及上述规则，不是对任意未知文本的保密证明。添加日志时必须遵守不采集正文和凭据的约定，不能依赖导出正则补救任意原始数据转储。

## 故障时导出

- React 渲染错误的备用界面保留「导出全部日志」按钮。
- 服务异常退出、渲染进程崩溃或启动失败时，原生提示提供「导出诊断包」，可导出后退出。
- 原生帮助菜单与 Electron 导出逻辑独立于 React 和 Go 服务；桌面导出不调用服务，也不打开书库数据库。
- 桌面主进程完全崩溃时，重新启动后可导出此前已经写入磁盘的日志。磁盘不可写时只保留有限内存尾部，并在清单报告丢失写入。
- 浏览器开发模式通过认证的 `POST /api/diagnostics/events` 记录前端事件，通过 `GET /api/diagnostics/export` 下载服务能访问的日志；浏览器没有桌面进程，服务停止后需要恢复服务才能读取磁盘日志。

无法读取或在导出过程中消失的日志会在清单中注明。桌面包存在缺失或写入失败时显示提示。文件写入失败不应阻止阅读、保存或已有 API 返回；取消系统保存对话框不生成诊断包。

日志能缩小问题范围，但依赖特定文件内容的解析/渲染问题可能仍需要用户另行提供样本。

## 手动验收

1. 在独立开发书库中启动桌面版，导入样本并打开、切换主题；从设置导出，检查 ZIP 含正常事件和运行环境，且没有文档或数据库。
2. 退出并重启，再导出，检查两次会话均在日志中。
3. 让开发环境服务异常停止，使用原生故障提示导出；确认不需要服务恢复。
4. 使用开发者工具触发未捕获异常，检查前端异常日志；React 错误备用界面和渲染进程崩溃路径由回归测试覆盖，人工检查原生帮助菜单仍可导出。
5. 取消保存，检查没有残留目标 ZIP；保存到不可写位置时应提示失败，可重新选择位置。

自动测试覆盖脱敏、跨会话/级别导出、旧翻译诊断、ZIP CRC、轮转和过期清理、符号链接边界、IPC frame 校验、离线桌面导出、React 错误界面以及 HTTP ResponseController Flush 兼容。全项目检查仍要求 `pnpm typecheck`、`pnpm test`、`pnpm build`。视觉验收采用人工检查。

## API 适配诊断

API 厂商规则、实际强度映射、上游错误分类和请求关联字段见 [API 厂商适配与错误诊断](api-provider-compatibility.md)。新增 API 错误事件只记录安全的结构化证据，不保存厂商可能回显正文的原始错误 message。

## PDF 本地解析诊断

`pdf.parse.start / spawned / stage / finish` 使用 `runId` 和 `documentId` 关联一次解析。记录原生 Canvas、ONNX Runtime 加载、PDF.js 加载、输出目录准备、模型校验、CPU 推理会话创建、PDF 读取与打开、逐页渲染/推理/文本提取、附件与清单写入等阶段。`stage` 是正在执行的阶段；后续阶段出现表示前一阶段已返回。失败时记录白名单异常类型和系统错误码、异常指纹，最终事件记录退出码、耗时、取消状态，以及标准错误的字节数、有限尾部指纹和截断标记。

不保存原始异常消息、调用栈或子进程标准错误正文，它们可能含 PDF 正文、文件名和用户路径。即使原生进程直接崩溃，Go 仍记录最后收到的阶段和退出码；尚未进入 JavaScript 时，最后阶段为 `bootstrap`。`exitCode=-1` 表示没有正常退出码（例如未启动或被信号终止），应结合阶段判断。`timeout` 表示解析子进程达到时间上限。

用户安装包含此改动的版本后，对同一 PDF 点击重试，等待成功或失败再导出诊断包即可。无需开启调试模式或提供书库数据库。新增日志用于定位故障，不代表已修复原有解析问题。

### 原生初始化崩溃的补充证据

阶段事件同步写入子进程管道，避免原生代码突然退出时丢失缓冲区内的最后阶段。每个阶段记录 Node/Electron 版本、进程 RSS、JS 堆与外部内存、系统可用及总内存；`session_create` 额外记录 ONNX Runtime 版本。系统可用内存是采样值，不能单独证明或排除内存不足。

开启 ONNX 初始化详细输出后，Go 在内存中按固定特征提取 `nativeDiagnostics`：线程池创建、会话初始化、图优化、张量初始化、初始化完成，以及 Crashpad 未连接、分配失败、Node 致命错误等。只导出固定分类码，不保存原始行；未知消息仍仅保留字节数与尾部指纹。分类跨管道分片且保留早期特征，内存使用有上限。分类码表示观察到的消息，不能替代原生崩溃栈或作为单独的根因证明。

最终事件的 `nativeTrace` 额外保留最近 32 个白名单原生源码文件名与行号（例如 `inference_session.cc:534`），不含本机路径和原始消息。它用于对照原生库源码缩小初始化内部的失败范围。

最终事件增加 `exitCodeHex`。Windows 的 `0xFFFF7003` 对应 Crashpad 未连接到崩溃处理程序，不能据此判断最初的异常原因。本次补充不会恢复旧诊断包中已丢弃的 stderr，也不保证所有原生崩溃均可仅凭日志确诊。
